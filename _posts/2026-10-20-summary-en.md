## [Ask HN Debates Shipping AI-Written Code Engineers Don't Understand](https://news.ycombinator.com/item?id=50151036) ⭐️ 8.0/10

An Ask HN thread, sparked by a Meta engineer's LinkedIn post about feeling uncomfortable shipping AI-generated code that acts as a "black box," drew 477 comments debating how engineers should handle code they don't fully understand. Commenters proposed design-first workflows, heavy testing, and strict code review as ways to maintain accountability. This discussion captures a growing industry-wide tension: AI coding assistants dramatically speed up development, but engineers risk losing deep understanding of the systems they ship. How teams resolve this will shape code review practices, engineering culture, and accountability standards across the software industry. Commenters suggested letting the LLM implement a design the engineer has already created (e.g., at the UML level), treating AI like a junior engineer whose work a principal engineer reviews, and compensating with more interactive testing. Others insisted that at least one person must be able to explain the code before it reaches production, warning that tests alone are insufficient.

hackernews · rzk · Oct 19, 11:24

**Background**: Large language models (LLMs) such as those behind AI coding assistants can generate large volumes of code quickly, but the output is not always fully traceable or easy to verify line by line. In traditional software engineering, code review and design documentation ensure that engineers understand what they ship; AI-generated code challenges these practices because reviewing every line can negate the speed gains. The thread reflects a broader debate about how accountability should work when AI contributes to production code.
